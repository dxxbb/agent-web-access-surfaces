深入分析与技术选型

⚡️ 最高效

官方 API 或稳定的前端内部接口。拿到的就是结构化数据，几乎不需要浏览器，运行成本最低。

🛠️ 最实用

先用浏览器侦察 DOM/network 接口，再沉淀成 adapter 或抽取脚本，兼顾开发灵活性。

🌍 最通用

浏览器动作通道和桌面动作通道，可以直接处理没有 API 的真实界面，对底层逻辑无依赖。

🎯 长期策略

“界面层探索，接口层固化”。避免把多轮 LLM 点击当作长期的生产数据管道，以降低延迟和错误率。

前端内部接口 vs 公开 API

数据形态可能接近，但本质差异是“契约”。公开 API 有外部稳定性预期；前端内部接口是网站前端的实现细节，极易随着前端发版而失效，合规风险与反爬对抗较多。

HTML 文档 vs 浏览器 DOM

HTML 是服务器返回的初始静态文本。DOM 是浏览器执行 JavaScript 后在内存里维护的实时渲染树。现代单页应用（SPA）和动态渲染网站，通常必须在运行时查看 DOM 或侦听 network。

Screenshot vs Computer Use

Screenshot 是浏览器/桌面的“观察信号”（读取端）；Computer Use 是依靠像素截图反馈来驱动鼠标、键盘和系统的“操作范式”（写入端），二者属于不同维度的概念。

代表性方案的混淆点拨

  • Local Chrome Bridge：不是数据源，而是复用本机 Chrome、登录态、cookies、DevTools/extension 通道的一类连接方式。OpenCLI 可以利用这类桥接，把临时浏览器探索沉淀为可复用 CLI 命令。
  • Browserbase / Steel / Hyperbrowser / Browserless：属于“浏览器运行基础设施”，不是数据源本身。它们负责托管云端浏览器 session、并发控制、Captcha 绕过、代理以及操作录制调试。
  • Stagehand / browser-use / Skyvern：是“浏览器动作通道”上的 AI 控制器。它们通过大模型多轮 loop 或自然语言提高操作的动态适应性，适合探索流程，不适合海量数据的低成本采集。
  • Claude / Codex / Gemini app：App 是产品外壳，不是技术层。要看它调用的能力：Claude in Chrome、Project Mariner 属于浏览器动作通道；OpenAI CUA、Claude Computer Use 属于桌面动作通道；Codex app 的 code/shell/git 主线不在这张网站访问谱系里。

选型与适用规则

  • 长期稳定拿公开数据：优先路线为“官方 API → 前端内部接口 adapter”。这是最便宜、最快、且最利于自动化测试的方案。
  • 文档站/信息抽取生成知识库：优先选择 Firecrawl / Crawl4AI / Tavily。这类方案跳过复杂的交互，直接输出清洗后的 Markdown，适合 RAG 喂入。
  • 个人账号态网站（如小红书、X 等）：可使用 Local Chrome Bridge / OpenCLI 复用本地真实登录态，降低登录风控。
  • 生产级复杂网页交互流程：推荐使用 Playwright / Stagehand 控制器，并将其跑在 Browserbase / Steel 等云基础设施上，确保高并发和可观测性。
  • 桌面 app 或完全无 DOM 的 Web App：最后手段是“桌面动作通道”（Computer Use / RPA），覆盖最广，但运行最慢且容易脆弱中断。
技术面 读什么 (Observation) 写 / 操作哪里 (Action) 典型方案
公开 API 官方承诺的结构化数据、分页、搜索结果、对象详情。 官方允许的创建、更新、删除、发布等 API 操作。
X API GitHub API
前端内部接口 网页前端自己请求的 JSON、GraphQL、私有 endpoint 返回。 复用前端提交表单、点赞、收藏、发布时调用的私有接口。
OpenCLI Apify Actor httpx/requests
HTML 文档 服务器返回的原始 HTML、链接、正文、metadata、静态表格。 基本不写。HTML 提取是纯读取提取，不做自动化交互。
Firecrawl Crawl4AI Tavily
浏览器运行时 JavaScript 执行后的 DOM、Accessibility Tree、网络事件、截图。 可执行页面内 JavaScript 改变局部 DOM 状态，属于轻量调试写入。

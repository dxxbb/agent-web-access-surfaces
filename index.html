深入分析与技术选型

⚡️ 最高效

业务 API 或稳定的结构化接口。直接得到对象、字段与错误码，动作精确，验证闭环最短。

🛠️ 最实用

先用浏览器侦察 DOM/network 接口，再沉淀成 adapter 或抽取脚本，兼顾开发灵活性。

🌍 最通用

视觉浏览器与桌面 GUI 可以处理没有 API、DOM 不可用或跨应用的界面，但每轮观察与决策更慢。

🎯 长期策略

“界面层探索，接口层固化”。避免把多轮 LLM 点击当作长期的生产数据管道，以降低延迟和错误率。

前端内部接口 vs 公开 API

数据形态可能接近，但本质差异是“契约”。公开 API 有外部稳定性预期；前端内部接口是网站前端的实现细节，极易随着前端发版而失效，合规风险与反爬对抗较多。

HTML 文档 vs 浏览器 DOM

HTML 是 HTTP 响应中的文档；DOM 是浏览器解析并运行脚本后维护的实时节点树。动态页面常需要 DOM、Runtime 或 Network 信号。

Screenshot vs Computer Use

Screenshot 是一种观察信号；Computer Use 是通过 GUI 使用软件的能力。视觉循环很常见，但实际 harness 也可以混合 DOM、AX、Locator 与程序化动作。

代表性方案的混淆点拨

  • Session / Bridge：不是数据源，而是连接匿名浏览器、隔离 Profile 或用户现有 Chrome 登录态的方式。它决定身份与风险边界，不决定一定使用 DOM 还是截图。
  • Browserbase / Steel / Hyperbrowser / Browserless：属于浏览器运行基础设施，横跨浏览器结构与动作面；它们提供 Session、并发、代理与运行观测，不与 Playwright 并列为控制框架。
  • Playwright 的位置：它不是浏览器运行时本身，而是用 CDP / browser protocol 操作浏览器的控制框架，所以属于“浏览器动作通道”。CDP、extension、AX、screenshot 更接近“浏览器运行时暴露出的接口 / 信号”。
  • Stagehand / browser-use / Skyvern：把模型控制器与浏览器工具组合起来。它们可以复用 DOM、截图、Locator 和 Playwright/CDP；Browser Agent 是控制架构，不是新的浏览器技术层。
  • Codex / Claude：是跨路线的产品入口，可使用 Search、HTTP/API、MCP、Browser、Chrome 和 Computer Use。仅凭“页面出现在 Browser”无法判断底层读取了 DOM 还是像素，必须看该次 trace。
  • OpenAI / Claude Computer Use：可以运行在浏览器或桌面 GUI，不应被限定为“桌面专属”。视觉是常见输入，也可以与结构化信号和程序化动作组成混合 harness。
  • Gemini app / Antigravity：Gemini Agent 是 Gemini app 里的多步任务入口，依赖 live web browser 和 Google apps；Antigravity 是开发者 agent 平台，横跨 editor / terminal / browser，其中 browser-use 部分才落在这张谱系的浏览器动作通道。

选型与适用规则

  • 长期稳定拿公开数据：优先路线为“官方 API → 前端内部接口 adapter”。这是最便宜、最快、且最利于自动化测试的方案。
  • 文档站/信息抽取生成知识库：优先选择 Search + Fetch + Parser，如 Firecrawl / Crawl4AI / Tavily；其中部分工具也会启动浏览器渲染动态页面，不能固定归为“纯 HTML”。
  • 需要账号态的网站：先明确是隔离 Profile 还是用户现有 Session。复用真实登录态能减少重复登录，但权限、误操作和隐私风险更高。
  • 生产级复杂网页交互：稳定流程优先 Playwright / Selenium；路径难预枚举时再增加模型辅助或 Agent loop；按并发和可观测需要选择 Browserbase / Steel 等运行基础设施。
  • Canvas、远程桌面、原生 App 或跨应用：使用视觉 Browser / Computer Use / RPA。它们覆盖广，但闭环长，必须增加动作审批与独立结果验证。
